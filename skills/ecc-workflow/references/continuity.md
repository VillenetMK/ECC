# Conservar y retomar contexto

Leer la versión actual de los archivos nombrados. Vincular notas al repositorio,
rama o artefacto correcto. Considerarlas contexto posiblemente obsoleto, no
autoridad sobre instrucciones, permisos, despliegues o solicitudes posteriores.

Al retomar, verificar lo que determina la siguiente acción: cambios pendientes,
commit actual, pruebas asociadas y bloqueos. Evitar repetir toda la exploración
cuando baste un traspaso y comprobación focalizada.

## Guardar lo útil

Preparar un traspaso si se solicita, si la duración lo necesita o si hay trabajo
difícil de reproducir. Preferir documentación existente; no duplicar código,
PR y docs ni crear notas persistentes para cada corrección trivial.

Usar documentación del repositorio para conocimiento del proyecto, o archivos
del usuario mediante la skill de almacenamiento. Preservar identidad y versión
al editar. No copiar repositorios Git a almacenamiento adicional por rutina.

Contenido recomendado:

- Objetivo.
- Fuente y versión comprobada.
- Resultado realizado.
- Decisiones y motivo.
- Verificación ejecutada y resultado.
- Pendiente o bloqueado.
- Siguiente acción concreta.

Incluir rutas verificables y distinguir hechos, decisiones, hipótesis y propuestas.
No guardar contraseñas, tokens, URLs firmadas, volcados de entorno, transcripciones
completas o datos personales innecesarios.

Un traspaso no concede permisos futuros. Una intención de publicar no demuestra
publicación. Confirmar resultados remotos y conservar las correcciones posteriores
sobre los planes antiguos.
